## 1. Что выяснили

- Жёлтая плашка LinkedIn в письме 23.11 не сбой. В конце `scan` (`vd/linkedin_browser.py`)
  упор в лимит карточек или конец прокруток записывается как ошибка, поэтому у тега
  `complete=False` и появляется «частичная выдача».
- В выпусках 70 (20.11) и 71 (23.11) из LinkedIn в письмо не дошло ничего: у всех тегов `passed=0`.
  Живой прогон на копии: из 35 постов 25 без роли аналитика в тексте, 10 не на русском, 0 прошли.
  Для этого среза подходящих вакансий не было. Вывод про весь LinkedIn делать нельзя.
- Пять русских хэштегов (#продуктовыйаналитик, #аналитикданных, #вакансия, #работа, #карьера)
  стабильно дают 0 карточек. Счётчик `vacancies` в статистике считает посты с найденной ролью,
  в том числе резюме соискателей, а не настоящие вакансии.
- Фильтра языка в поиске по постам нет. Русскую выдачу даёт только русский текст в запросе.

## 2. Что изменено (в коммитах)

- `config.yaml`: `max_posts_per_tag` 12→20, `max_scrolls_per_tag` 1→2, `total_timeout_sec` 360→1000.
  Разовые 1200 с на 23.11 сохранены.
- `vd/linkedin_browser.py`: лимит карточек считается по новым постам (`len(posts)`), а не по
  просмотренным. Известные карточки по-прежнему стоят около 3 с: ID поста берётся только через меню.
- `vd/sources/linkedin_posts.py`: `unique_tags` принимает запросы из 1–6 слов, к слову можно
  добавить `#`. Кавычки, `&`, переводы строк и более шести слов отклоняются.
- `tests/test_linkedin_posts.py`: два новых теста. Полный набор: 296 OK.
- `README.md`: оформлен по скиллу beautify-github-readme, картинки в `assets/readme/`.
  Ветка слита с `main` (конфликты только в README). PR в `main` создаёт пользователь сам:
  https://github.com/konicaRu/vacancy-digest/compare/main...feat/cross-source-dedup?expand=1

В `config.yaml` запросы-фразы пока не добавлены, список тегов не менялся.
