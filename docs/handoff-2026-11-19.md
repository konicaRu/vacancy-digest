## 2. Что реализовано и какие файлы изменены

- `vd/duplicates.py`: конкретные ссылки/ID, консервативные смысловые пометки, архивный пакет в памяти.
- `vd/store.py`: добавочные таблицы публикаций, сущностей, кодов отправок и предположений; запись в общей транзакции. Старый ledger сохраняется, старые коды после повторной отправки доступны для отметок.
- `vd/models.py`, `vd/classify.py`: метаданные работодателя/исходного текста/связей; защита от разных ID, грейдов и объединения несовместимых позиций через публикацию без ID.
- `vd/sources/jabka.py`: чтение JobPosting полной карточки (до 20 запросов), работодатель/текст/ссылки отклика, сохранение исходной карточки при ошибке.
- `main.py`, `vd/digest.py`: интеграция архива, отметок текущего запуска, HTML/text пометок, ссылок на источники и счётчиков наблюдения.
- `tests/test_duplicates.py`, `tests/fixtures/dedup_avito.json`: регрессии и реальная публичная пара. README/ARCHITECTURE/дизайн/план/память обновлены.
- Рабочая база не менялась проверочными прогонами; добавочная миграция выполнится при штатном открытии Store новым кодом. Код проверяется на копии. Шесть будущих выпусков ещё не наблюдались.

Для другого компьютера нужны этот документ, дизайн и предыдущая передача. Рабочая SQLite и `out/` не передаются Git и могут быть недоступны; секреты не прикладывать.

## 3. Технические решения и причины

Направление и дизайн утверждены пользователем. Реализованы следующие правила:

- Подтверждение идентичности: каноническая ссылка на конкретную вакансию или ID в пространстве работодателя/системы найма. Общие контакты и страницы карьеры не доказательство.
- Смысловое сравнение только создаёт предположение; не объединяет сущности и не переносит applied/reviewed. Различия команды, грейда, обязанностей и явных ID учитываются против совпадения.
- Архив расширяется добавочными таблицами вакансий, публикаций, связей отправок и предположений; существующие ключи ledger, коды и статусы не переписываются. Учитывается несколько вакансий в одном посте-подборке.
- jabka обогащается полными карточками и ссылками; Telegram использует текст/ссылки поста. Сбой обогащения оставляет исходную карточку.
- Для начала детерминированное осторожное сравнение содержательных частей описаний; отдельный внешний AI-сервис и embeddings не требуются. Нельзя обещать обнаружение любых перефразировок.
- Новое состояние фиксируется вместе с seen/bookmarks/ledger только в успешной ветке отправки/пустого выпуска; rollback, SMTP failure и dry-run его не записывают. Текущий служебный журнал runs сохраняется.
- Наблюдать минимум шесть успешных штатных выпусков. Скрытие по смыслу не включается автоматически по истечении срока. Прогоны --force, dry-run, failed и выпуски с предупреждениями в счётчик не входят.
- Пометка требует >=12 общих содержательных слов, >=0.5 пересечения от меньшего набора, одинаковых работодателя и направления команды в заголовке, отсутствия разных ID/грейдов. Шаблон условий исключается. Метод не распознаёт любые перефразировки.

Нечёткое сравнение одних заголовков отклонено из-за ложного объединения разных команд. Obsidian не нужен для решения задачи и не входит в объём реализации.

## 4. Обнаруженные проблемы и решения

Реальный пример: jabka «Аналитик данных для команды модерации» (`vd-20261118-am-1`) и FreeWorkFeed/4295 «Аналитик данных в команду модерации» (`vd-20261118-pm-6`). В сохранённой jabka-карточке нет исходной Avito-ссылки, а в Telegram есть vacancy 20883. Теперь пара на фикстуре получает пометку, сохраняя обе карточки; ID из jabka не придумывается. Массовая дозагрузка прошлых описаний не выполняется.

Отрицательная регрессия: «Аналитик данных для оценки качества модерации» (`vd-20261118-am-4`) остаётся отдельной. Независимое ревью воспроизвело три ложных объединения: несовместимые ID через третью публикацию без ID, пагинацию как ID, две вакансии одного поста. Все исправлены с RED→GREEN тестами. Дополнительно проверены перенаправление всей группы и противоречие грейда.

Продолжение ревью выявило ещё два Important: потерю связи старого кода при совпадении URL после окна и обход ограничения формата через синдицированную копию. Оба исправлены RED→GREEN: точная ссылка связывает сущность независимо от возраста, а дата доставки управляет подавлением; явно запрещённая удалёнка конкретной карточки учитывается как доказательство для того же ID. Архивное ограничение учитывается в пределах окна точного дедупа от наблюдения ограничения. Один Minor отложен: при нескольких подходящих смысловых совпадениях выбирается первое, а не лучшее; влияет лишь на ссылку пометки.

CodeGraph в текущей сессии вернул `Transport closed`; использовано прямое чтение файлов. Git read-команды выводили предупреждение о недоступном глобальном ignore, но завершались успешно.
