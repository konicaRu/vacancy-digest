# LinkedIn browser pilot

Контроллер поиска LinkedIn для `sources.linkedin_posts`. Использует установленный Google Chrome
в видимом режиме, отдельный профиль и включённую песочницу. Вход выполняет пользователь.
`main.py` вызывает `vd/sources/linkedin_posts.py` через локальный `vd/linkedin_bridge.py`;
результаты проходят общий классификатор, архив и транзакцию после успешной отправки письма.

Из корня проекта (установка только в игнорируемый out/, без изменения .venv):

```powershell
.venv/Scripts/python.exe -m pip install --index-url https://pypi.org/simple --target out/linkedin-browser-playwright/packages -r tools/linkedin_browser_pilot/requirements.txt
.venv/Scripts/python.exe tools/linkedin_browser_pilot/browser_session.py
```

Контроллер открывает LinkedIn и остаётся запущенным. Все локальные данные находятся в
`out/linkedin-browser-playwright/`: `profile/`, `status.json`, `command.json`, `response.json`.
Пароли, cookies и storage не извлекаются; profile/ не копировать в Git или передачу контекста.
Перед запуском убедиться, что другой контроллер не использует этот профиль, а в command.json
не осталась старая команда close. Профиль не удалять: он хранит ручной вход.

Команды — JSON в command.json; каждый запрос получает новый непустой id. Пример:

```json
{"id":"state-001","action":"state"}
```

`state` возвращает только URL/заголовки вкладок. `search` принимает url только на
`https://www.linkedin.com/search/results/content/`. `read_results` читает текст и видимые ссылки
только в main страницы поиска, не на странице входа или в ленте. `close` завершает контроллер.
`scan_posts` принимает один `hashtag`, `days`, `max_posts`, `max_scrolls`, `timeout_sec` и `seen_ids`;
раскрывает полный текст, копирует публичную ссылку через меню поста и разрешает lnkd.in в стабильный ID.
Буфер обмена читается только после собственного копирования ссылки, прочий текст не сохраняется.
Возвращает `posts`, `scanned`, `seen`, `complete`, `errors`. Ссылки постов очищаются от query/rcm.
`scan_profile` вместо `hashtag` принимает `profile` (`https://www.linkedin.com/in/<id>/` или
`/company/<id>/`) и открывает «Все действия» человека или «Публикации» компании. Дата читается до
копирования ссылки; у человека чтение останавливается на первом посте старше `days`. Дополнительно
возвращает `undated` — сколько постов пропущено без распознанной даты. После обновления кода
контроллер нужно перезапустить (`close`): новую команду знает только новый процесс.
Ждать response.json с совпадающим id; старый ответ не означает выполнения новой команды.

Формат поиска, проверенный вручную:

```text
https://www.linkedin.com/search/results/content/?keywords=%23productanalyst&datePosted=%22past-week%22&sortBy=%22date_posted%22
```

В штатном запуске `autostart: true` поднимает контроллер из этой папки с существующим профилем.
Планировщик должен работать от вошедшего пользователя (Interactive); текущая задача VacancyDigest
соответствует этому условию. Если вход истёк или появилась защита, источник покажет ошибку,
остальные источники продолжат работу. Авторизацию программно не вводить, защиту не обходить.

Активация — `start_date: "2026-11-20"`; до этой даты источник пропускается, кроме dry-run.
Лимиты задаются в config.yaml: отдельный запрос на каждый тег, неделя, до 12 карточек и одной
прокрутки на тег, общий бюджет 360 секунд. Первые три — #hiring, #ProductAnalyst, #AnalyticsJobs.
Неполный текст не помечается прочитанным; ошибки/лимиты видны в письме. Нет гарантии полного
охвата LinkedIn. Известные посты не разворачиваются повторно; отредактированные старые посты
повторно не сканируются. Состояние фиксируется только после отправки; dry-run ничего не доставляет.

Не запускать второй контроллер вручную, если первый занят. `request.lock` защищает IPC от
одновременных запусков системной блокировкой, которая освобождается при аварии. Сам файл не удалять.
Если состояние
непонятно, закрыть только это окно Chrome, проверить status.json и controller.stderr.log, затем
запустить снова. Профиль не удалять. Один прогон не доказывает устойчивость длительного сбора.
