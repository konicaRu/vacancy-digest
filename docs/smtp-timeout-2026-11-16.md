# Таймаут отправки 16 ноября 2026

## Наблюдения

Утренние запуски 09:33 и 10:15 МСК собрали вакансии, но SMTP завершился
`curl (28) server response timeout`. Состояние отправленных вакансий не продвигалось.
Вечер 13 ноября был успешен, утро того дня также завершилось таймаутом.

Файл для curl создавался через `EmailMessage.as_bytes()` с политикой по умолчанию:
заголовки и тело разделялись LF вместо SMTP CRLF. Исправление ограничено
`msg.as_bytes(policy=SMTP)`; сервер, порт 465, TLS и способ авторизации сохранены.

## Проверки

- Регрессионный тест читает реальные байты файла, проверяет CRLF-разделитель
  заголовков и отсутствие одиночных LF/CR. До изменения он падал, после — проходит.
- Локальный SMTP-эксперимент показал, что curl добавляет корректный терминатор DATA
  в обоих случаях. Гипотеза отсутствующего терминатора не подтвердилась.
- Штатный запуск 61 (11:41:38–11:45:36 МСК) после исправления успешно отправил
  36 вакансий (28 подходят, 8 уточнить), без ошибок источников. В SQLite статус
  `sent`, зарегистрированы все 36 кодов отметок.
- Дополнительное последовательное сравнение на настроенном Яндекс-аккаунте:
  одинаковое содержимое HTML, тот же curl, сервер, порт 465 и авторизация;
  диагностические темы, Message-ID и MIME boundaries создавались отдельно.

| Формат файла | Протокол | Итог |
|---|---|---|
| LF (старый) | 220 → EHLO/250 → AUTH/235 → RCPT/250 → DATA/354; финального 250 нет | curl 28, 46,03 с при лимите 45 с |
| CRLF (исправленный) | 220 → EHLO/250 → AUTH/235 → RCPT/250 → DATA/354 → 250 | curl 0, 1,06 с |

Сравнение не меняло SQLite/закладки. Сохранённые результаты и скрипт находятся
локально в `out/smtp-ab-result.json` и `out/probe_smtp_ab.py`, вне Git.
Полный verbose-вывод не сохранялся: он может содержать данные авторизации.
Полный набор тестов перед коммитом: 142, OK; есть предупреждение ResourceWarning
незакрытого сокета в остальных тестах. `git diff --check` без ошибок.

## Вывод

Сбой воспроизведён со старым LF-форматом после DATA и не воспроизводится с CRLF
на том же порту сразу после него. Это сильное подтверждение проблемы формата
сообщения, а не необходимости перехода на порт 587. Внутреннее поведение Яндекса
без серверных логов неизвестно; единичное сравнение не исключает все временные
сетевые факторы. Проверить следующие автоматические выпуски.

Успех здесь означает SMTP-принятие, а не отдельную проверку папки «Входящие».
Автоматические повторные отправки после неоднозначного таймаута не добавлялись:
они могут создавать дубли.
