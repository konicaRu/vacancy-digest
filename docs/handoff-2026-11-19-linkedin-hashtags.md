- `vd/sources/linkedin_posts.py`: независимые хэштеги, casefold дедуп запросов, канонические activity ID,
  полный текст, разделение нескольких вакансий с сохранением общих ограничений и грейдов.
- `vd/linkedin_browser.py`: видимый Chrome, область результатов Posts, неделя/свежие, раскрытие всех
  текстовых блоков включая комментарий автора перепоста, ссылки через стандартную команду меню.

  Чтение закреплено за componentkey карточки, чтобы перестройка выдачи не смешала ссылку и текст.
- `vd/linkedin_bridge.py`: UUID IPC, ограниченные ожидания, один активный запрос; автозапуск
  отслеживаемого контроллера из tools/ с существующим профилем. Живой занятый процесс не дублируется,
  системная блокировка запроса освобождается даже при аварии, файл request.lock не удаляется.
  Сбой источника изолирован в collect_all.
- `vd/classify.py`: только Python для `linkedin:posts`, русский основной текст, существующий профиль,
  исключение junior/intern, business/system, закрытия и явных запретов; remote без отдельного
  подтверждения РФ принимается, неизвестный формат идёт в unknown_format. Остальные источники
  сохраняют свой маршрут классификации. Установка/запуск LM Studio не нужны этому источнику.
- `vd/duplicates.py`: при `run.permanent_confirmed_dedup: true` подтверждённые исходный ID/URL либо
  точная публикация не возвращаются после 30 дней. Сходство без сильного ID остаётся пометкой;
  одинаковая общая должность/компания у разных постов LinkedIn не подтверждает повтор.
  Несколько вакансий в одном посте имеют разные части/коды.
- `vd/digest.py`, `main.py`: общий утренний/вечерний выпуск, автор, статистика каждого тега в HTML,
  тексте и runs.stats_json. Записи seen/ledger/архива — существующей транзакцией после SMTP.

## 3. Технические решения и причины

Параметры — `sources.linkedin_posts` в config.yaml. Первыми идут #hiring, #ProductAnalyst,
#AnalyticsJobs, затем остальные целевые/общие теги дополнения, без дубликатов регистра.
Источник включён, `start_date: "2026-11-20"`: штатный поиск начинается завтра. Dry-run разрешён
до даты активации для проверки. Сегодняшний вечерний выпуск не подключает новый источник.
Окно семь дней, до 12 карточек и одной прокрутки на тег, общий бюджет 360 секунд. Бюджет может
не дать дойти до поздних тегов — это отражается в статистике и предупреждении, полного охвата нет.
Истёкшая авторизация/защита/неполный текст дают ошибку или предупреждение, не ложный пустой успех.
Известные посты повторно не раскрываются: изменения старых публикаций отдельно не отслеживаются.

Контроллер: `tools/linkedin_browser_pilot/browser_session.py`. Данные только локально в
`out/linkedin-browser-playwright/`: packages/, profile/, IPC/status и логи. Профиль не удалять,
не копировать в Git/передачу, cookies и пароли не извлекать. Вход уже выполнен пользователем;
проверенный перезапуск Chrome сохранил его и открыл авторизованную ленту. На другом компьютере
восстановить зависимости по README и войти вручную. Системные сертификаты не устанавливать.

Задача Windows `VacancyDigest` проверена: Ready, Interactive, после входа +10 минут и ежедневно
в 17:00; запускает run_digest.bat из этой рабочей папки. Для видимого Chrome нужна сессия вошедшего
пользователя и доступная сеть. Задача не запускает компьютер сама и не восстанавливает VPN.

## 4. Обнаруженные проблемы и решения

- Динамическая выдача меняла порядок карточек после временной вкладки: чтение закреплено
  за componentkey вместо изменчивого номера. Команда копирования меню при необходимости
  открывается повторно один раз. Последние живые выборки дали полный текст/ссылки 12 из 12 карточек.
- При разделении терялись нумерованные заголовки, суффиксы Junior/стажёр и общие ограничения
  страны. Исправлено с RED/GREEN регрессиями. Описание продукта «фото/видео» после роли отделено
  от названия, чтобы стоп-слово «фот» не скрывало подходящего Product Analyst.
- Удаление устаревшего request.lock допускало гонку двух владельцев: заменено системной
  блокировкой байта (msvcrt.locking в Windows), файл не удаляется, авария освобождает блокировку.
- Ограниченный охват, истечение входа, изменения DOM и обновления старых постов остаются
  ограничениями. Не повторять headless на пустом профиле и не вводить авторизацию программно.

нумерованные вакансии и общие условия, межисточниковые ID, бессрочный сильный дедуп и отсутствие
склейки общих названий, IPC, интеграцию collect_all/Store/digest и отказ SMTP/dry-run.
Независимое ревью выявило потерю суффиксов грейда и общего вступления; регрессии воспроизведены
до исправлений, после исправлений проходят. Последний полный прогон: **291 тест OK, 11.957 с**;
лог: `out/linkedin-final-tests.txt`. Регрессия из живого поста также проверена: описание продукта
«фото/видео редакторы» после названия роли больше не срабатывает как стоп-слово должности «фот».
Грейды в скобках/после роли сохранены, SQL/Python/описание продукта не подменяют должность.

Повторная проверка перед commit/push: **291 тест OK, 11.576 с**, лог
`out/pre-push-linkedin-hashtags-tests.txt`; `git diff --check` без ошибок.

Живые результаты, профили и копии SQLite остаются в игнорируемом out/:
