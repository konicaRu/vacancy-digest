# Audit fixes Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task. Preserve existing uncommitted Tochka/Ostrovok work.

**Goal:** Исправить три подтверждённых дефекта аудита и добавить ограниченные сетевые повторы.
**Architecture:** Точечные изменения классификации/дедупа, долговечная очередь недочитанных подборок
в существующей SQLite-транзакции после отправки, повторы только читающего HTTP fetch.
**Tech Stack:** Python, SQLite, requests, unittest.
**Spec:** out/project-review/review-2026-11-18.md; пользователь подтвердил исправление.

## Global Constraints

Рабочую SQLite и почту не менять при проверках. TLS сохраняется. Старые отметки и журнал
совместимы; уже потерянные исторические карточки автоматически не переотправлять.
Работать в текущей папке, сохраняя несвязанные незакоммиченные изменения. Commit/push не запрошены.

## Review Focus

- Разные команды/ID одной компании сохраняются и в письме, и отдельными строками ledger.
- Старые ключи журнала и отметки продолжают работать; одинаковые URL и явные дубли объединяются.
- Подборка после таймаута/лимита сохраняется в очередь; после успешного дочитывания удаляется;
  при сбое отправки и dry-run очередь/seen/bookmarks не меняются.
- Запрет удалёнки и ограничения страны сильнее положительного ответа LLM/форматной метки;
  положительные «удалёнка или офис на выбор», РФ и «без релокации» остаются допустимыми.
- Повторы не затрагивают SMTP/Google Form submit, не отключают TLS и имеют конечный бюджет.

## Rulings and review ledger

- Ключ ledger включает канонический URL, схема старых строк и коды отметок не переписываются.
  Точное название+компания оставлены для межисточникового сопоставления; различие team-названий
  или разных карточек одного сайта не скрывается. Цена: возможны дополнительные дубли вместо потерь.
- При ошибке вложенной подборки кэшируется её собственный payload; via хранит исходный
  включённый канал. Непрочитанные ссылки и корни без попыток получают очередь раньше уже
  опробованных. Основание: ревью воспроизвело зависание цепочки при бюджете1; новые тесты проходят.
- Шаблоны ограничений включают поля «Удалённая работа: нет», Remote(EU only),
  only-for-residents. Положительный выбор офиса/удалёнки проверен отдельно по замечанию ревью.
- Старое ожидание title-only fallback в test_expand заменено на отложенное чтение.
- Проверка реального сетевого прогона идёт на копии старой БД: backup выполняется ДО Store(),
  чтобы новая таблица очереди создавалась как обычная миграция. Рабочая БД не меняется.
