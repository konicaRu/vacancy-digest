# Подключение Хабр Карьеры, Авито и Aviasales

Статус: согласован пользователем 12.11.2026 («делай»); реализация и проверка по плану `superpowers/plans/2026-11-12-company-sites.md`.

## Результат для пользователя

В утреннее письмо добавляются новые подходящие вакансии с трёх сайтов. Это обычные группы источников
с существующими ссылками «Откликнулся» и «Разобрал группу». Вечером эти три источника не обходятся.
Текущие Telegram-каналы, jabka и youngjunior продолжают работать по прежнему расписанию.

## Рассмотренные подходы

1. Подключить сначала Хабр Карьеру, Авито и Aviasales через requests + BeautifulSoup.
   Карточки присутствуют в HTML; можно использовать текущий стек без браузерной автоматизации.
   Этот вариант выбран пользователем.
2. Сразу разбирать все сайты первой очереди, включая API, JavaScript и ограничения доступа.
   Охват больше, но объём и неопределённость выше. Остальные сайты остаются в бэклоге.

## Сбор и отбор

- Три отдельных адаптера источников с общим контрактом `SourceResult` и устойчивыми идентификаторами вакансий.
- Хабр: поиск по русским и английским названиям аналитических ролей, листание выдачи с ограничением страниц.
  Авито и Aviasales: сбор ссылок из списка активных вакансий; отдельно проверить полноту списка и пагинацию.
- Уже виденные вакансии пропускать. Перед загрузкой подробностей отсеивать заведомо неподходящие названия
  по существующим запросам профиля, без добавления новых стоп-слов.
- У подходящих по названию новых вакансий читать полное описание: формат работы, ограничения по стране,
  грейд и ссылки на hh. В текст для классификации включать данные вакансии, без меню и общих блоков сайта.
- Существующие фильтры, дедупликация, корзины и отметки сохраняются. Признак удалёнки в карточке
  дополняется полным описанием, чтобы не пропускать явные ограничения по России.
- При первом запуске брать вакансии за последние 5 дней, если дата публикации известна.
  Если источник даты не отдаёт — один раз обработать текущие активные вакансии; далее новизна по `seen`.
  Это предлагаемый выбор реализации, а не ранее согласованное правило пользователя.

## Расписание и состояние

- Новые источники имеют настройку утреннего обхода; в вечерний выпуск не добавляются как якобы пустые источники.
- `--dry-run` позволяет проверить их в любое время без отправки письма и изменения состояния.
- Состояние записывается только после успешной отправки, через текущий механизм Store; схему БД менять не требуется.
- Известная пустая выдача означает «новых вакансий нет». Неизвестная вёрстка, блокировка, ошибка загрузки списка
  или описания означают сбой источника, а не отсутствие вакансий. При сбое источник не продвигает своё состояние.
- Если достигнут лимит страниц, показывать предупреждение о неполном чтении.

## Объём и проверка

Новые адаптеры, регистрация в `main.collect_all`, утренний режим, конфигурация и читаемые названия в письме.
Без новых зависимостей, автооткликов и браузерной автоматизации.
Незакоммиченную правку релокации, существовавшую до этой работы, не переписывать.
