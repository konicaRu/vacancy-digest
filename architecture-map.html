Актуальность. Снимок, не живой источник правды. Автоматически не обновляется. При расхождении с кодом верить коду, карту поправить. Обновлять по «гит сейв», только когда менялись структура, схема БД, расписание или автоматика — и только после вопроса пользователю «структура изменилась — обновить карту?».

Назначение

purposeДважды в день (после входа в Windows и в 17:00) собрать вакансии продуктового аналитика и аналитика данных, которые можно делать удалённо из России, и прислать одно письмо. Отклики отмечаются из письма одним кликом.
owner_profileПродуктовый аналитик, Череповец, ищет только удалёнку из РФ; hh.ru — вручную, не в агенте
done_criterion_v17 дней подряд: оба выпуска приходят сами, ни один источник не «не прочитан» два выпуска подряд, отметки подхватываются, в каналах нет подходящих вакансий, которых не было в письме. Отсчёт с 21.10.2026.
repohttps://github.com/konicaRu/vacancy-digest
statusv1 работает по расписанию, только в рабочие дни РФ; модель LM Studio выключена; LinkedIn выключен
languageрусский (ответы, документы, письмо)

Петля отметок: письмо → «✓ Откликнулся» / «☑ Разобрал группу» → Google Таблица → следующий выпуск. Подробная схема с ссылками на код — architecture-flow.html.

Гварды и гочи — неочевидное

  • --dry-run ничего не запоминает: каждый пробный прогон видит одно и то же. --force отправляет и СДВИГАЕТ закладки — не использовать «для проверки», пока отбор не готов.
  • Удалить data/state.sqlite = начать с нуля: первый запуск берёт lookback_days_first_run (5) дней.
  • jabka: 1-я страница ≈ сутки вакансий; без листания теряются. На 1-й странице бывают старые закреплённые карточки — остановка по «нет свежих непросмотренных», а не по первой старой.
  • Telegram: get_text("\n") рвёт заголовки между <b>-тегами («Senior Data» вместо «Senior Data Аналитик в Банк 131») — только _text (строки по <br>).
  • Подборки бывают вложенными (подборка → пост-подборка) и цитатами со ссылкой «Откликнуться» (mtsbankcareer) — формат работы проверяется по тексту самой цитаты.
  • title_queries: include — целым словом («аналитик» не ловит «для аналитики»), exclude — по началу слова; проверяется только должность до « — ».
  • Новые Google Формы — черновики: пока не нажата «Опубликовать», formResponse отвечает «Документ не опубликован».
  • Коды отметок vd-test-* игнорируются (тестовые письма). У письма 20.10 15:17 кодов нет — его вакансии отметить нельзя.
  • Письмо статично: отметку в нём не видно; :visited Яндекс не применяет (проверено). Список откликов — таблица ответов формы.
  • Яндекс сам ссылки в письмах не открывает (проверено vd-test2-noclick) — иначе GET-отметки срабатывали бы ложно.
  • Триггер 17:00, зарегистрированный после 17:00, сработает только завтра (StartWhenAvailable не догоняет время до регистрации).
  • LM Studio: `lms` не поднимает сервис без открытого окна («Timed out waiting for LM Studio daemon») — поэтому модель выключена. Модель путает «не подходит» с «нельзя удалённо» — guard_llm.
  • Отмеченные (applied/reviewed) не возвращаются никогда; остальные — дедуп 30 дней.
  • Коммит и push — только после «да» пользователя; тесты перед коммитом.
  • Дедуп с журналом: у большинства вакансий нет компании — ключ «|название» не используется, дубль только по той же ссылке.
  • Компания jabka в карточке — «@ | Компания» (разные части текста).
  • Упавший запуск шлёт письмо «СБОЙ агента» (не в --dry-run) — молчание означает «ничего не запускалось».
  • --force в уже отправленный выпуск даёт коды vd-…-am2-N — иначе одна отметка попала бы на две вакансии.
  • Нерабочий день по календарю: запуск выходит сразу и НЕ пишет в runs — пустой журнал за выходные это норма.
  • На этом компьютере бывают короткие сбои DNS/SSL (4 случая за 19–21.10) — источник «не прочитан» на выпуск; повтора запроса пока нет.
  • Меню канала «Вакансии │ Стажировки │ … │ Удалёнка │ …» (young_june, newdirections, bigtechjobs) убирается из текста — иначе «Удалёнка» = «удалённо из РФ».
  • young_june / newdirections — junior/стажировки (youngjunior.ru); bigtechjobs делит подборки на «Стажёр: / Junior: / Middle:» — грейд берётся из раздела.
  • youngjunior.ru — НЕ признак junior: через него идут и Middle-вакансии bigtechjobs.
  • api.hh.ru /vacancies и /employers без токена приложения — 403 (справочники открыты); выдуманный email в User-Agent — «blacklisted».

Структура репозитория

main.pyоркестрация запуска: выпуск утро/вечер → рабочий день? → сбор → подборки → отбор → дедуп → отметки → письмо → SMTP → коммит состояния; при падении — письмо «СБОЙ»; флаги --dry-run --force --no-llm --stats
vd/config.pyчитает config.yaml и secrets.env каждый запуск; без конфига — остановка
vd/models.pyItem (сырой элемент: text, anchors, blocks, via), Verdict (разбор + bucket, num), SourceResult
vd/sources/telegram.pyt.me/s/<канал>, пагинация ?before=, один пост ?embed=1; текст строками по <br> (_text); цитаты со ссылкой → Item.blocks
vd/sources/jabka.pyвыдача jabka.work, листает &page=N пока есть свежие непросмотренные карточки
vd/sources/linkedin_mail.pyписьма LinkedIn по IMAP (выключено)
vd/expand.pyподборки → отдельные вакансии: ссылки-названия, вложенные, цитаты, «Подборка…» с одной ссылкой; грейд вакансии из раздела подборки (section_grade → Item.grade_hint)
vd/classify.pyпредфильтр (в т.ч. ссылка на hh.ru), keyword_classify, title_match, decide (корзины, грейд из подборки), guard_llm, dedup (+ junior-двойники из других каналов)
vd/llm.pyклиент LM Studio (OpenAI-совместимый, JSON-схема)
vd/marks.pyссылки на форму, разбор CSV таблицы → {код: applied|reviewed}
vd/workcal.pyрабочий ли день: календарь года с isdayoff.ru → кэш; не скачался — «пн–пт» + предупреждение
vd/digest.pyHTML + текст письма: группы по источникам, номера, «✓ Откликнулся», «☑ Разобрал группу», таблица источников, плашки
vd/mailer.pySMTP; «отправлено» только если сервер принял адресата
vd/store.pySQLite: закладки, seen, ledger, runs; commit_after_send — одна транзакция после отправки
tests/unittest; tests/samples/ — живые страницы Telegram
config.yamlисточники, profile.title_queries, mail, marks, llm, run (once_per_slot, evening_hour)
run_digest.bat / setup.bat / register_task.ps1запуск (лог → logs/scheduler.log), установка .venv, регистрация задачи

База данных

data/state.sqlite (в .gitignore); рядом кэш календаря data/calendar-<год>.txt

bookmarkssource PK, value, updated_at — Telegram: id последнего поста; jabka: время чтения
seen(source, external_id) PK, first_seen — что уже разобрано
ledgerdedup_key PK, title, company, url, source, bucket, reported_at, status (new|applied|reviewed), code (vd-ГГГГММДД-am|pm-N)
runsid, run_date, started_at, finished_at, status (running|sent|empty|failed|dry-run), stats_json, error; упавший запуск закрывается failed (Store.fail_running)

Правило записи: bookmarks + seen + ledger + статусы отметок — одной транзакцией commit_after_send, только после того как SMTP принял письмо
Миграции: Store.__init__: ALTER TABLE ledger ADD COLUMN code, если колонки нет

Автоматика

taskVacancyDigest (register_task.ps1)
triggersпри входе в Windows + 3 мин, ежедневно 17:00 (время компьютера = МСК)
settingsStartWhenAvailable, RunOnlyIfNetworkAvailable, лимит 1 час
slotsвыпуск = утро (am) до run.evening_hour=17, вечер (pm) после; каждый не чаще раза в день (Store.sent_in_slot по started_at)
workdaysписьма только в рабочие дни производственного календаря РФ (run.workdays_only): в нерабочий день выход до начала запуска; --force / --dry-run — в любой день
