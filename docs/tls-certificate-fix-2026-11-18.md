# TLS банков — исправление 18.11.2026

## Причина

Т-Банк предъявляет цепочку `*.tbank.ru` → Russian Trusted Sub CA → Russian Trusted Root CA.
Дополнительный корень отсутствует в стандартном certifi. Это вызывает
`SSLCertVerificationError: self-signed certificate in certificate chain`.
С добавлением только этого официального корня проверка проходит у обоих банков.

Корень скачан обычным Requests с включённой проверкой HTTPS по ссылке из
[официальной инструкции Т-Банка](https://status.tbank-online.com/certificates/):
https://help-static2.tbank-online.com/certs/Windows/Root/Russian_Trusted_Root_CA.cer

DER SHA-256: `d26d2d0231b7c39f92cc738512ba54103519e4405d68b5bd703e9788ca8ecf31`.
Сертификат побайтно совпал с корнем цепочки Т-Банка; срок до 27.02.2032.

## Исправление

`vd.sources.make_session` монтирует отдельный HTTPAdapter только для точных origin
`https://www.tbank.ru/` и `https://job.alfabank.ru/`. Его SSLContext содержит обычные
корни certifi плюс `vd/certs/russian-trusted-root-ca.pem`. Проверка цепочки и имени
остаётся обязательной. Прочие хосты, включая похожие имена, используют обычный адаптер.
Явно заданный CA-файл пользователя (включая REQUESTS_CA_BUNDLE) сохраняет приоритет.

Windows, файл certifi, системные настройки и глобальное доверие не менялись.
Загрузка сертификата нужна только при разработке/обновлении: в запуске он берётся из проекта.
Минимум Requests поднят до 2.32.3: метод настройки TLS pool-context отсутствует в 2.32.2.
Текущее окружение содержит Requests 2.34.2, дополнительная установка не требовалась.

## Проверка

- Тесты локальных реальных TLS-рукопожатий до исправления воспроизводили сбой доверия.
- После исправления доверенные сертификаты принимаются для обоих банков; неправильное
  имя хоста и неизвестный самоподписанный сертификат отвергаются; чужие хосты/похожие
  имена дополнительного доверия не получают; явный CA override соблюдается даже после
  успешного соединения через тот же Session.
- Полный набор: 199 тестов, OK. Независимое ревью: минимум Requests исправлен по замечанию,
  других блокирующих замечаний нет.
- Полный живой сбор через **рабочий** main.make_fetcher, без verify=False и отдельного CA override:
  Т-Банк — 342 карточки, 44 запроса, 1 прошла текущие фильтры;
  Альфа-Банк — 23 новые карточки, 62 старые, 7 запросов, 3 прошли фильтры.
  Оба источника без ошибок и предупреждений. Количество активных карточек меняется на сайте.
- Результаты: out/tls-diagnosis/{tbank,alfabank}-verified-collection.json (вне Git).

Почта, рабочая SQLite, отметки откликов и планировщик при проверке не менялись.
