## 1. Что добавить

В список поисковых хэштегов LinkedIn включить три явно запрошенных тега:

- `#hiring` — уже был среди базовых; **сохранить**, не создавать второй идентичный запрос;
- `#ProductAnalyst` — целевой тег для продуктовой аналитики;
- `#AnalyticsJobs` — дополнительный тег вакансий в аналитике.

Общий стартовый набор:

```text
#vacancy
#hiring
#hr
#jobs
#вакансия
#работа
#карьера
#ProductAnalyst
#AnalyticsJobs
#DataAnalyst
#ProductAnalytics
#BIAnalyst
#продуктовыйаналитик
#аналитикданных
```

**Важно:** для дедупликации поисковых запросов приводить хэштеги к единому регистру (`#ProductAnalyst` и `#productanalyst` — один поисковый тег), но в конфиге оставить привычную человеку запись. Не рассчитывать, что LinkedIn всегда одинаково обрабатывает регистр: проверить на пилоте.

## 2. Логика поиска

1. Сканировать выбранные хэштеги **как независимые поисковые запросы**, а не требовать, чтобы все теги встречались в одном посте.
2. По возможности применять фильтр **Posts / Публикации**, сортировку по свежести и временной период последней недели для стартового теста.
3. Собирать постоянную ссылку/ID, дату, автора, полный текст поста и ссылку на саму вакансию, если она есть.
4. Один пост, найденный по нескольким тегам, считать одним постом; если в нём несколько разных вакансий, выделять их отдельно.
5. Вести метрики по каждому тегу: просмотрено, найдено новых, признано вакансиями, прошло фильтры, уже встречалось, ошибки/неполный текст.
6. Не полагаться на получение полного охвата LinkedIn: браузерный пилот доказывает только работоспособность конкретных запросов. Соблюдать правила площадки; не обходить капчу или защитные механизмы.

## 3. Фильтрация только Python (LLM не обязательна)

Использовать уже имеющийся в проекте классификатор `vd/classify.py` и словари/регулярные выражения вместо нового AI-конвейера. `llm.enabled: false` должно оставаться рабочим режимом.

**Обязательные проверки:**

- Основной текст вакансии на русском языке (смешанные русский текст и английские названия технологий допустимы); один только русский хэштег недостаточен.
- Роль: продуктовый аналитик / аналитик данных / подходящий BI-аналитик; Middle/Senior; junior/intern, системные и бизнес-аналитики исключаются.
- Работа удалённая; **отдельного подтверждения найма из РФ не требовать**, если нет явного ограничения, исключающего РФ. Офис, обязательный гибрид и релокация — исключение.
- Сопоставить стек и задачи с `profile.about`, `profile.title_queries` и другими существующими правилами. SQL, Python, BI, продуктовые метрики, A/B — признаки соответствия, но не требовать все одновременно.
- При отсутствии в посте явной информации о формате работы — категория «формат уточнить», не выдавать как подтверждённую удалёнку; публикации с неоднозначным языком/ролью отправлять на ручную проверку, а не приписывать им факты.

Ввести три понятных результата: `main` (подходит), `unknown_format` (уточнить), `drop` (не подходит). Для диагностики хранить причины решений. Балльная оценка по резюме — **дополнительная**, а не замена обязательных проверок.

## 4. Повторы — обязательно

- Использовать общую SQLite и `vd/duplicates.py`, а не отдельный список для LinkedIn.
- Сначала дедуп по стабильному ID/URL поста (чтобы не читать одну публикацию несколько раз); затем по конкретной ссылке/ID вакансии работодателя; затем консервативная сверка компании, должности и содержания между LinkedIn, Telegram и сайтами.
- **Требование пользователя:** подтверждённая вакансия, уже попавшая в отправленный дайджест, в следующих дайджестах больше не появляется. Это сильнее действующего обычного окна в 30 дней: продумать отдельную долговременную политику для подтверждённой сущности без ошибочного склеивания разных вакансий.
- Не скрывать разные грейды, команды или реальные вакансии с разными ID только из-за похожего заголовка. Сомнительные смысловые совпадения лишь помечать.
- Состояние обработанных/отправленных данных фиксировать по существующей транзакционной схеме; при неудачной отправке письма не помечать вакансию как доставленную.

## 6. Порядок выполнения и критерии приёмки

1. **Пилот:** проверить три новые записи в наборе поиска (для `#hiring` убедиться, что не возник дубль запроса). Получить полный текст и стабильную ссылку хотя бы для части свежих результатов. Сохранить отчёт по каждому тегу.
2. **Фильтры Python:** протестировать русскоязычные, англоязычные, смешанные посты, junior, офис/гибрид, удалёнку и явный запрет РФ. Запускать без LM Studio.
3. **Дедуп:** тестировать повтор одного поста под разными тегами, перепост в Telegram, совпадение вакансии с корпоративным сайтом и похожие, но разные вакансии.
4. **Интеграция:** пробный `--dry-run --force --no-llm`, без записи в рабочую SQLite и отправки письма; затем тест на копии базы и штатный запуск после отдельной проверки.
5. **Готовность:** в дайджест попадают только новые соответствующие вакансии, повторные не приходят, источник не останавливает остальные при сбое, статистика объясняет отбор; отправка работает без LLM.
