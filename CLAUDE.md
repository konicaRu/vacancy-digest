В конце сессии допиши запись в «Журнал» в `memory.md`. Отвечай по-русски.

## Как работать (из project-starter, разделы 3–5)

- **Принципы Карпатого:** думай до действия (при неоднозначности — варианты и вопрос, противоречия выводи);
  минимализм (ровно то, что решает задачу); точечные изменения (каждое прослеживается к просьбе);
  работа от критерия (тесты + живой прогон). При написании и правке кода вызывай скилл `karpathy-guidelines`.
- **Не обобщай молча:** после правки по конкретному месту спроси — разовая правка или общее правило?
  Правилом (в `config.yaml`, код, документы) делать только после моего «да».
- **Хирургически:** `Edit` нужного фрагмента, не затирать мои ручные правки, готовое задним числом не переписывать.
- **Кратко:** без пересказа; ход длинной работы — процентом готовности («готовность 60%»), не длинным текстом.
- **Вопросы по одному:** один вопрос — один ответ.
- **Superpowers:** новая функция → `brainstorming`; код → `test-driven-development`; баг → `systematic-debugging`;
  перед «готово» и коммитом → `verification-before-completion`.
  Приоритет: мои правила > CLAUDE.md > Superpowers > поведение агента по умолчанию.

**«гит лоад»** (начало сессии) — прочитать `memory.md` + `ARCHITECTURE.md`, кратко доложить, где остановились. Только чтение.
**«гит сейв»** (конец блока работы) — обновить ВСЕ ТРИ, не один вместо другого:
1. `memory.md` — запись в «Журнал», «Статус», «Открытые вопросы», «Следующие шаги»;
2. `ARCHITECTURE.md` — строка в «Changelog» + сверить текущие разделы (модули, хранилище, отбор, конфигурация) с кодом;
3. `README.md` — если изменение касается того, что в нём описано (письмо, источники, установка, команды).
Затем тесты → проверка, что `secrets.env` не в индексе → коммит и push — **только после моего «да»**.
Тесты: `python -m unittest discover -s tests -t .` — должны проходить перед коммитом.
Секреты только в `secrets.env` (он в .gitignore), в код и в git их не кладём.
