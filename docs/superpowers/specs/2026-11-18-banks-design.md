# Т-Банк и Альфа-Банк

Пользователь согласовал следующую партию: Т-Банк + Альфа-Банк, только подтверждённая удалёнка из РФ.
Добавить оба источника в существующие утренний и вечерний обходы с текущими фильтрами должностей,
дедупликацией и отметками откликов. Первый обход — 14 дней при известной дате; без даты — активные карточки.

## Подходы

- HTML каталога: у Т-Банка SSR отдаёт только первую порцию; у Альфа-Банка каталог загружается клиентом.
- Публичные API самих сайтов: полная пагинация и структурированный формат работы. Выбран этот вариант.

Т-Банк: POST `/pfpjobs/papi/getVacancies`, фильтры ACTIVE/T_CAREER, русское и английское названия,
пагинация offset/limit/isFinished/totalCount. POST getVacancyDescription, статус published,
метка «Удаленный» в tags; без метки удалёнка не подтверждена. Ссылки ведут на публичные карточки.
Альфа-Банк: GET `job.alfabank.ru/api/vacancies`, text/skip/take/total, детали по id;
jobTypes с key=1003 и value «Дистанционная работа». Скрытые, внутренние и истёкшие карточки исключаются.
Полные описания сохраняют ограничения РФ/релокации для существующего классификатора.

Сбой/неполная структура — SourceError без продвижения закладки, лимит обхода — предупреждение.
TLS-проверка сохраняется. Диагностические ответы получены без проверки TLS из-за недоверенной
цепочки сертификатов текущей сети; это не считается успешной рабочей сетевой проверкой.
Изменение main.make_fetcher: необязательный json для читающих POST API, старые GET без изменений.
Письма, рабочую SQLite и расписание при проверках не менять. Коммит/push не входят в запрос.

## Проверка 18.11

Исходный набор 181 тест, итоговый 194 — OK; diff --check без ошибок. Независимое ревью без блокеров.
У Т-Банка реально встречаются SEO-имена с заглавными буквами и точкой, а также внешние
переадресации стажировок без seoSlug: последние исключаются до создания Item.
Альфа-Банк в некоторых detail-ответах отдаёт opaque base64/url-safe id; личность такой карточки
проверяется по неизменному полному slug и точному названию. Реальные случаи покрыты тестами.

Диагностический полный обход (без проверки TLS только в out/banks-probe/live_check.py):
Т-Банк — 344 карточки после исключения redirect, 44 запроса, 1 прошла текущие фильтры;
Альфа-Банк — 23 новые карточки, 62 старые исключены по createdAt, 7 запросов, 3 прошли.
Ошибок/предупреждений адаптеров нет. Это отбор до межисточниковой дедупликации.
Публичные ссылки обоих банков проверены: HTTP 200 и правильная карточка, в том числе
Т-Банк с URL moscow для публикации другого города — UUID выбирает правильную вакансию.

Рабочий fetch с TLS не прошёл: SSLCertVerificationError, self-signed certificate in certificate chain
на www.tbank.ru и job.alfabank.ru. Источники включены, но в текущей сети для штатного сбора
нужно устранить причину недоверенной цепочки. Проверка TLS не отключена в продукте.
Рабочая SQLite, отметки откликов, почта и планировщик не менялись.

## TLS-блокер устранён

По следующему запросу пользователя добавлено доверие официальному Russian Trusted Root CA
только для двух origin банков внутри make_session. Полный штатный сбор с TLS успешен:
Т-Банк342 карточки/44 запроса, Альфа-Банк23 новые+62 старые/7 запросов, ошибок и предупреждений нет.
199 тестов OK. Подробности и источник сертификата — `docs/tls-certificate-fix-2026-11-18.md`.
